## らいぶレンズ: アプリ指定オーバーレイ

- オーバーレイの対象を「画面全体」と「アプリ指定（特定ウィンドウ）」で切り替えられるようにした（[ADR-002](../docs/ai/decisions/ADR-002-app-window-target.md)）
  - 操作パネルに「対象」セクションを追加（ラジオで切り替え・ウィンドウ選択リスト・一覧を更新・追従状態の表示）
  - アプリ指定では、オーバーレイが対象ウィンドウの範囲だけに重なり、200ms のポーリングで移動・リサイズに追従。最小化・終了などで見失うとオーバーレイを隠して通常モードに戻し、見つかり直すと自動で表示を戻す
  - 通常モードでも対象ウィンドウに細い枠を表示
- ウィンドウ一覧の取得に `get-windows`（v9）を追加。ESM 専用のため main から動的 import。`asarUnpack` に追加。macOS でタイトルを出すには「画面収録」の権限が必要（ない場合はアプリ名のみ表示し、パネルに案内を表示）
- アプリ指定中のマーカーは `windowCoordinate`（ウィンドウ左上からの相対座標）＋ `AppWindowRef`（アプリ名・bundleId・パス・タイトル）で登録。オーバーレイは現在の対象に属するマーカーだけを描画し、操作パネルの一覧には所属（画面 / アプリ名）を表示
- バックグラウンド操作は Phase 2 で実装する前提で、`ActionDelivery`（foreground / background）型と、`ForegroundDriver` / `BackgroundDriver`（macOS `CGEventPostToPid`・Windows `PostMessage`）の設計を ADR-002 に記録
- IPC に `windows:list` / `overlay:set-target` を追加し、main で入力検証（`kind` の値・`windowId` が現在の一覧に存在するか）
- 確認: `npm run lint` / `npm run build` が通ることを確認。テスト用の別プロセスのウィンドウを対象にして、DevTools Protocol 経由で次を確認
  - オーバーレイの bounds がウィンドウに一致し、移動・リサイズに追従する（記録モードのまま）
  - 相対座標でマーカーが登録され、描画位置が相対座標と一致する
  - 最小化で lost になり通常モードへ戻る、復帰で ok に戻る
  - 画面全体に戻すと `coordinate` で登録され、画面のマーカーだけが描画される
  - 存在しない windowId / 不正な kind は拒否される
- 修正: 操作パネル以外から対象を切り替えたとき、パネルの「アプリ指定」表示が追従しなかった問題（main の状態を優先するようにした）
- 未確認: Windows 実機、マウスでの実操作の目視確認

## らいぶレンズ: マーカーの順次実行

- 操作パネルに「実行」セクションを追加し、登録したマーカーを上から順に実カーソルで操作できるようにした（[ADR-003](../docs/ai/decisions/ADR-003-sequential-run.md)）
  - マーカーごとに操作（クリック / ダブルクリック / 右クリック、既定はクリック）と、操作後の待機秒数（既定 1 秒、最大 60 秒）を操作パネルで設定できる
  - 実行中は一時停止・再開・停止ができる。エラー時は内容を表示し、再試行か停止を選べる
  - 進捗（`i / 全体`）と現在のマーカーを操作パネルで強調表示。オーバーレイは実行中だけ画面全体に広がり、実行位置にリングと番号を表示する（クリック透過のまま）
  - 実行中だけグローバルショートカット `Esc` で緊急停止できる。`Cmd/Ctrl+Shift+N` でも停止する
- マウス操作に `@nut-tree-fork/nut-js`（4.2.6）を追加。main から動的 import。Windows は物理ピクセルに変換して渡す。macOS は開始時にアクセシビリティ権限を確認し、ない場合は案内付きで開始を断る
- アプリ指定のマーカーは実行のたびにウィンドウを探し直し、相対座標から画面座標を計算する。最前面でなければ nut.js の `Window.focus()` で前面に出す（macOS は失敗時に `open -b` へフォールバック）
- IPC に `marker:update` / `run:get-state` / `run:start` / `run:pause` / `run:resume` / `run:stop` / `run:retry` / `run:state-changed` を追加。実行中はモード変更・対象変更・マーカーの編集 / 削除を main で拒否。`marker:update` は操作の種類と待機時間の範囲を検証
- 確認: `npm run lint` / `npm run build` が通ることを確認。テスト用の別プロセスのウィンドウを対象に、DevTools Protocol 経由で次を確認
  - アクセシビリティ権限がない状態では、案内文付きで開始が拒否される
  - ドライバを一時的にダミー（操作内容をファイルに記録するだけ）に差し替えて、3 つのマーカーが登録順・設定した操作の種類・正しい画面座標（ウィンドウ位置 + 相対座標）で実行され、終了後に通常モードへ戻る
  - 実行中はオーバーレイにヒントと実行位置が表示され、操作パネルの対象・モードが無効化される。実行中のモード変更・マーカー削除は拒否される
  - 待機中の一時停止で待機時間が進まず、再開・停止で以降のステップが実行されない
  - 対象ウィンドウを最小化するとエラーになり、復帰後の再試行で最後まで実行される。エラーからの停止もできる
- 修正: 対象ウィンドウを最小化したとき、同じアプリ（別インスタンス）のウィンドウを代わりに操作してしまう問題。オーバーレイが追従中のウィンドウがあれば、そのウィンドウだけを使うようにした
- 未確認: nut.js による実際のクリック（開発用の Electron にアクセシビリティ権限が必要）、Windows 実機
