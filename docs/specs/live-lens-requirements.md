# らいぶレンズ 開発指示

Electronで「らいぶレンズ」というデスクトップアプリを開発する。

## 目的

PC画面上に透明なオーバーレイを表示し、そのオーバーレイを使って**画面上の操作を登録・記録・実行できる自動操作ツール**を作る。

単純なマクロ再生ではなく、

* 画面上の位置を指定して操作する
* 操作を記録する
* 操作手順を保存する
* 登録した操作を順番に実行する
* 必要に応じて画面状態を確認してから次の操作へ進む

ことを目的とする。

---

# 1. 透明オーバーレイ

アプリの中心機能として、他のアプリの画面上に透明なオーバーレイを表示する。

イメージ：

```text
┌────────────────────────────────────┐
│ 他のアプリの画面                   │
│                                    │
│       ┌──────────────┐             │
│       │              │             │
│       │ 透明領域      │             │
│       │              │             │
│       └──────────────┘             │
│                                    │
└────────────────────────────────────┘
```

オーバーレイ自体は透明で、背後のアプリが見える。

---

# 2. オーバーレイの用途

透明オーバーレイを以下の用途に使用する。

### 操作対象の指定

ユーザーが画面上のボタンなどをクリックすると、その位置を操作対象として登録する。

```text
画面

        ┌─────────┐
        │ 保存    │
        └─────────┘
             ↑
        クリックして登録
```

登録時には対象位置を視覚的に表示する。

例：

```text
        ┌─────────┐
        │ 保存    │
        └─────────┘
          ┌───┐
          │ ① │
          └───┘
```

---

# 3. オーバーレイの表示モード

オーバーレイには複数のモードを用意する。

## 通常モード

透明で、背後のアプリを普通に操作できる。

## 記録モード

ユーザーのクリック位置や操作対象を取得する。

クリックした場所を視覚的に表示する。

## 編集モード

登録済みの操作対象を表示する。

例：

```text
① 保存ボタン
② 次へボタン
③ 閉じるボタン
```

それぞれの位置をオーバーレイ上に表示する。

## 実行モード

自動操作中の対象をオーバーレイ上に表示する。

```text
          ┌─────────┐
          │ 保存    │
          └─────────┘
              ↑
          ● 実行中
```

現在実行している操作がどこなのかをユーザーが確認できるようにする。

---

# 4. クリック透過

自動操作中や通常表示時は、オーバーレイが背後のアプリへの操作を邪魔しないようにする。

Electronの透過ウィンドウを利用し、必要に応じてクリック透過を切り替える。

概念：

```text
通常
Overlay → click-through

記録
Overlay → 操作可能

編集
Overlay → 操作可能

実行
Overlay → click-through
```

---

# 5. 操作ステップ

自動操作は「ステップ」の集合として管理する。

例えば、

```text
① A画面
   ↓
② ボタンをクリック
   ↓
③ 2秒待機
   ↓
④ B画面になるまで待つ
   ↓
⑤ 保存ボタンをクリック
```

という形。

UIではステップを一覧表示する。

```text
┌──────────────────────────────┐
│ らいぶレンズ                  │
│                              │
│ ① A画面                      │
│ ② 保存ボタンをクリック        │
│ ③ 2秒待機                    │
│ ④ B画面を確認                │
│ ⑤ 保存ボタンをクリック        │
│                              │
│ [記録] [実行] [停止]          │
└──────────────────────────────┘
```

---

# 6. 対応する操作

最初に以下を実装する。

### マウス

* クリック
* ダブルクリック
* 右クリック
* マウス移動
* ドラッグ

### キーボード

* キー押下
* 複数キーの同時押し
* テキスト入力

### 待機

* 指定時間待機
* 指定画面になるまで待機

---

# 7. 操作記録

「記録開始」を押すと記録モードになる。

ユーザーが実際に行った操作を記録する。

例えば、

```text
記録開始
↓
保存ボタンをクリック
↓
文字入力
↓
Enter
↓
次へボタンをクリック
↓
記録停止
```

これを自動的にステップとして登録する。

オーバーレイ上にも登録した操作番号を表示する。

```text
        ┌─────────┐
        │ 保存    │
        └─────────┘
             ①

        ┌─────────┐
        │ 次へ    │
        └─────────┘
             ②
```

---

# 8. クリック位置

クリック対象は絶対座標だけに依存しない設計にする。

## 絶対座標

```json
{
  "type": "coordinate",
  "x": 500,
  "y": 300
}
```

## 正規化座標

```json
{
  "type": "normalized",
  "x": 0.5,
  "y": 0.3
}
```

## 画像認識

将来的に、

```text
登録したボタン画像を探す
↓
見つかった位置をクリック
```

という方式にも対応する。

そのためクリック対象は、

```text
coordinate
normalized
image
text
```

などを切り替えられる構造にする。

最初はcoordinate方式を実装する。

---

# 9. 画面状態の確認

重要なのは、単純に時間だけで操作を進めないこと。

例えば、

```text
A画面
↓
クリック
↓
画面が変化
↓
B画面が表示される
↓
B画面を確認
↓
保存ボタンをクリック
```

というように、**画面の状態を確認してから次の操作を実行できる構造**にする。

---

# 10. 画像による画面認識

画面の一部を登録し、その画像が表示されたことを検出できるようにする。

例：

```json
{
  "type": "waitForImage",
  "image": "screen-b.png",
  "timeout": 10000
}
```

screen-b.pngが画面上に表示されたら次のステップへ進む。

10秒経過しても検出できなければエラーにする。

将来的にはOCRによる文字認識も追加する。

---

# 11. 操作データ

操作手順はJSONで管理する。

例：

```json
{
  "name": "A→B保存処理",
  "version": 1,
  "steps": [
    {
      "id": "step-001",
      "name": "A画面",
      "waitFor": {
        "type": "image",
        "image": "screen-a.png",
        "timeout": 10000
      },
      "actions": [
        {
          "type": "click",
          "target": {
            "type": "coordinate",
            "x": 500,
            "y": 300
          }
        }
      ]
    },
    {
      "id": "step-002",
      "name": "保存",
      "actions": [
        {
          "type": "click",
          "target": {
            "type": "coordinate",
            "x": 800,
            "y": 400
          }
        }
      ]
    }
  ]
}
```

---

# 12. 自動操作の実行

「実行」を押すと、ステップを上から順番に実行する。

```text
Step 1
 ↓
画面状態確認
 ↓
Action
 ↓
Step 2
 ↓
画面状態確認
 ↓
Action
```

現在実行中のステップをUIとオーバーレイの両方に表示する。

例：

```text
✓ ① A画面
✓ ② 保存
▶ ③ B画面
  ④ 保存
```

オーバーレイ：

```text
       ┌─────────┐
       │ 保存    │
       └─────────┘
            ↑
         ▶ ④
```

---

# 13. 一時停止・停止

実行中は、

```text
[一時停止]
[停止]
```

を表示する。

### 一時停止

現在の自動操作を停止し、再開できる。

### 停止

自動操作を完全に終了する。

---

# 14. エラー処理

画面認識に失敗した場合などはエラーとして扱う。

例：

```text
B画面を検出できませんでした
```

選択肢：

```text
[再試行] [停止]
```

最初のバージョンではこの2つだけでよい。

---

# 15. 自動操作エンジン

UIとOS操作を分離する。

```text
AutomationRunner
├── run()
├── pause()
├── resume()
├── stop()
├── executeStep()
├── executeAction()
├── waitForCondition()
└── handleError()
```

OSのマウス・キーボード操作は別モジュール。

```text
AutomationController
├── click()
├── doubleClick()
├── rightClick()
├── move()
├── drag()
├── keyPress()
└── typeText()
```

画面認識も別モジュール。

```text
ScreenRecognizer
├── capture()
├── findImage()
└── waitForImage()
```

---

# 16. Electron構成

```text
Electron
│
├── Main Process
│   ├── AutomationRunner
│   ├── AutomationController
│   ├── ScreenRecognizer
│   └── Overlay Window
│
├── Preload
│   └── IPC API
│
└── Renderer
    ├── 操作一覧
    ├── 操作編集
    ├── 記録UI
    ├── 実行UI
    └── オーバーレイUI
```

Rendererから直接OS操作を実行しない。

OS操作はMain Process側で管理し、IPC経由でRendererと連携する。

---

# 17. オーバーレイと操作UI

通常の設定画面とは別に、画面上に表示するオーバーレイを持つ。

```text
通常ウィンドウ
┌─────────────────────┐
│ 操作一覧             │
│                     │
│ ① 保存              │
│ ② 次へ              │
│ ③ 完了              │
│                     │
│ [記録] [実行]        │
└─────────────────────┘

             ↓

デスクトップ上

┌────────────────────────────────┐
│ 他のアプリ                    │
│                                │
│       ┌──────────┐             │
│       │ 保存     │ ← ①        │
│       └──────────┘             │
│                                │
│             ┌──────────┐       │
│             │ 次へ     │ ← ②  │
│             └──────────┘       │
└────────────────────────────────┘
```

オーバーレイは、登録した操作対象・現在実行中の操作・選択範囲などを視覚的に示すために使用する。

# 18. 実装フェーズ

## Phase 1：透明オーバーレイ

まず以下を実装する。

* Electron透明ウィンドウ
* 常に最前面への表示
* クリック透過の切り替え
* オーバーレイの表示・非表示
* 画面座標の取得
* オーバーレイ上へのマーカー表示

---

## Phase 2：基本自動操作

```text
クリック
ダブルクリック
右クリック
キー入力
テキスト入力
待機
```

を実装する。

---

## Phase 3：操作登録

```text
操作追加
↓
クリック位置指定
↓
ステップ作成
↓
ステップ一覧表示
↓
保存
```

を実装する。

---

## Phase 4：操作記録

```text
記録開始
↓
ユーザー操作
↓
自動的にステップ化
↓
記録停止
```

を実装する。

---

## Phase 5：自動再生

登録したステップを順番に実行する。

```text
Step 1
↓
Step 2
↓
Step 3
↓
Step 4
```

一時停止・再開・停止にも対応する。

---

## Phase 6：画面認識

```text
画面画像登録
↓
画面監視
↓
対象画像を検出
↓
次のステップへ
```

を実装する。

---

## Phase 7：認識ベースの操作

最終的に、

```text
「このボタンを押す」
```

を座標ではなく、

```text
画像
OCR文字
画面状態
```

から判断できるようにする。

---

# 19. 最初の完成目標

最初からすべてを実装せず、まず以下を完成させる。

```text
① 透明オーバーレイを表示
② クリック透過を切り替え
③ オーバーレイ上で操作位置を指定
④ クリック操作を登録
⑤ ステップとして保存
⑥ ステップを順番に実行
⑦ 実行中の位置をオーバーレイで表示
⑧ 一時停止
⑨ 停止
```

この段階で実際に、

```text
A画面
↓
ボタンをクリック
↓
B画面
↓
ボタンをクリック
```

という一連の操作が自動実行できることを確認する。

その後、操作記録 → 画像認識 → OCR認識の順で拡張する。

---

# 20. 開発ルール

* 既存コードがある場合は最初にプロジェクト全体を確認する
* 既存アーキテクチャを可能な限り維持する
* 不要なリファクタリングをしない
* 必要最小限の変更で実装する
* RendererとMain Processの責務を分離する
* OS操作はMain Process側で管理する
* オーバーレイと通常UIを分離する
* 操作データはJSONで管理する
* 後から画像認識・OCRを追加できる設計にする
* 実装後はlint・buildを実行する
* まずPhase 1〜3を完成させ、動作確認してから次のPhaseへ進む

まず現在のプロジェクト構成を確認し、Phase 1の透明オーバーレイ実装から開始する。
